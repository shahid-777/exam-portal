I/O Organization

How a computer talks to the keyboard, disk, printer and every other device. Short notes with diagrams.

1. I/O Interface

Definition: An I/O interface is a small circuit placed between the CPU and a device. It lets two very different parts understand each other.

Why do we need it?

  • Speed gap: the CPU works in nanoseconds, a keyboard in milliseconds.
  • Format gap: devices may use different voltages, codes and word sizes.
  • Control: something must say which device is chosen and when to start.

Main parts inside

  • Data register holds the data being moved.
  • Status register tells the CPU if the device is busy or ready.
  • Control register carries commands such as start or stop.
  • Address decoder checks whether the CPU is calling this device.

2. PCI Bus

PCI (Peripheral Component Interconnect) is a fast bus that connects add-on cards (sound, network, graphics) to the processor.
  • 32-bit or 64-bit wide, runs at 33 or 66 MHz. A 32-bit, 33 MHz bus gives about 133 MB/s.
  • Plug and Play: the system finds and sets up a new card by itself.
  • A bridge joins the PCI bus to the CPU bus, so each side can run at its own speed.
  • Any card can become a bus master and move data without bothering the CPU.

3. SCSI Bus

SCSI (Small Computer System Interface) is a parallel bus used mainly for disks, tapes and CD drives. Many devices share one cable.
  • Narrow SCSI: 8 devices (IDs 0 to 7). Wide SCSI: 16 devices.
  • The host adapter connects the bus to the computer and takes one ID.
  • Devices are joined in a daisy chain: one after another on the same cable.
  • Both ends of the cable need a terminator. It stops signals from bouncing back.
  • Every device has a unique ID. A device that starts a request is the initiator; the one that answers is the target.

4. USB (Universal Serial Bus)

USB is a simple serial connection for almost any device: keyboard, mouse, pen drive, phone, printer.
  • Works as a tree. The host is the root, hubs branch out, devices are the leaves. Up to 127 devices.
  • Cable has 4 wires: power (+5 V), ground, and two data wires (D+ and D−).
  • Hot plug: connect or remove a device while the computer is running.
  • Supplies power to small devices, and detects the device speed automatically.

5. Data Transfer

Data moves between devices in different ways. We classify it in two ways: how bits travel and how the timing is agreed.

Synchronous vs Asynchronous

  • Synchronous: sender and receiver follow one common clock. Fast and simple, but both sides must keep the same speed.
  • Asynchronous: no common clock. Each transfer is announced by a control signal (strobe) or a two-way handshake (request and acknowledge). Works for devices of any speed.

6. Modes of Data Transfer

There are three ways to move data between a device and memory. They differ in how much work the CPU does.

Example: Polling is like checking the oven every minute. Interrupt is like setting a timer. DMA is like asking someone else to cook the whole meal.

7. Direct Memory Access (DMA)

DMA lets an I/O device transfer data to or from memory without passing through the CPU. A special chip, the DMA controller, manages it.

DMA controller registers

  • Address register: where in memory the block starts.
  • Word count register: how many words to move.
  • Control register: direction (read/write) and mode.

Steps

  • 1. CPU loads the address, count and direction into the controller.
  • 2. The device asks for transfer with a DMA request.
  • 3. Controller asks the CPU for the bus (HOLD). CPU replies HLDA and lets go of the bus.
  • 4. Controller moves the data directly to memory and counts down.
  • 5. At count zero it sends an interrupt to the CPU: transfer complete.

Types of DMA transfer

  • Burst mode: whole block in one go. CPU is blocked for that time.
  • Cycle stealing: controller takes the bus for one word at a time, between CPU cycles.
  • Transparent mode: controller uses the bus only when the CPU is not using it.

8. I/O Processor (IOP)

I/O Processor is a separate small processor built only for I/O work. It can fetch and run its own instructions, called a channel program.
  • CPU only sends a short command: "do this I/O program in memory". Then it carries on with its own work.
  • The IOP handles many devices, checks errors, converts data formats, and interrupts the CPU at the end.
  • It talks to memory directly, like DMA, but it is far smarter.
