S6. The DOM: how JavaScript sees your page

DefinitionThe DOM (Document Object Model) is a tree-shaped copy of your HTML page that the browser keeps in memory. JavaScript uses the DOM to find elements and change them.
Real-life exampleA family tree. Grandfather (html) has two children (head, body). Body has its own children (h1, p, button). To change something, JavaScript first finds the right person in the tree, then changes it.
Find an element, then change it 
<h1 id="title">Hello</h1>
<script>
  const heading = document.getElementById('title');   // FIND
  heading.textContent = 'Welcome, students!';          // CHANGE
</script>
  1. document means "the whole page".
  2. getElementById('title') finds the element whose id is title.
  3. We keep it in the variable heading.
  4. .textContent = ... replaces its text. The page changes instantly.

Other ways to find: document.querySelector('.big') finds the first match using a CSS selector. document.querySelectorAll('p') finds all matches.

1. Scripting Web Pages

Scripting a web page means writing JavaScript that makes the page react and change.

Real-life exampleA shop's display board is HTML: it just shows prices. If the shopkeeper wants the board to change the price when you press a button, he needs electronics inside. JavaScript is that electronics.
DefinitionScripting a web page means using JavaScript (a scripting language) to read and change the HTML and CSS of a page after it has loaded, and to respond to what the user does.
Words to know
Script
A small program written in a scripting language such as JavaScript.
Static page
A page that never changes (only HTML and CSS).
Dynamic page
A page that changes by itself or by user action (HTML, CSS and JavaScript).

What can scripting do?

  • Show or hide things (menus, pop-ups).
  • Check a form before sending (is the email correct?).
  • Update part of the page without reloading (live cricket score, notifications).
  • Do calculations (EMI calculator).
  • Load data from a server (list of products).
Example: a button that changes the page 
<h1 id="msg">Good morning</h1>
<button id="btn">Change greeting</button>

<script>
  const msg = document.getElementById('msg');
  const btn = document.getElementById('btn');

  btn.addEventListener('click', () => {
    msg.textContent = 'Good evening';
    msg.style.color = 'green';
  });
</script>
  1. The first two lines find the heading and the button in the DOM.
  2. addEventListener('click', ...) means "when this button is clicked, run the following function".
  3. Inside the function we change the heading text and its colour.
Try it yourselfMake index.html, paste the example, open it in Chrome. Click the button: the text and colour change without reloading the page. Now change it so a second click returns the text to "Good morning" (hint: use an if that checks the current msg.textContent).
Common mistakes
  • Writing the script above the elements it uses (the page does not exist yet, you get null). See topic 3.
  • Writing getElementById('#msg'). Do not put # there; that is only for querySelector.
Exam answerScripting web pages means using JavaScript to make web pages dynamic and interactive. A script can access the DOM to change HTML content and CSS styles, handle user events such as clicks, validate forms and fetch data from servers without reloading the page.

2. Embedding JavaScript Code in HTML Pages

"Embedding" means putting your JavaScript inside or linking it to your HTML page so the browser can run it.

Real-life exampleYou can write notes on the page of the book itself (internal), or keep a separate notebook and write "see my notebook, page 5" in the book (external). Both work, but the separate notebook is easier to manage.
DefinitionThere are three ways to add JavaScript to HTML: (1) internal code inside a <script> tag, (2) external code in a .js file linked with <script src>, (3) inline code inside an HTML attribute like onclick.

Way 1: Internal script

<body>
  <p id="p">Waiting...</p>
  <script>
    document.getElementById('p').textContent = 'JavaScript is running';
  </script>
</body>

Good for: small demos with one page.

Way 2: External script (recommended)

Create a file app.js and link it. The file contains only JavaScript, with no <script> tags inside.

<!-- index.html -->
<script src="app.js"></script>

// app.js
console.log('External file loaded');

src means "source": the path to the file. If the file is in the same folder, just write its name. If it is in a folder, write src="js/app.js".

Way 3: Inline script (avoid)

<button onclick="alert('Clicked')">Click</button>

It works, but it mixes HTML and JavaScript and becomes messy in big projects.

Words to know
Cache
The browser saves a copy of a file so the next visit is faster.
Path
The address of a file inside folders, like js/app.js.
Try it yourself1) In a folder, create index.html and app.js. 2) In app.js write document.body.style.background = 'lightyellow';. 3) In index.html add <script src="app.js"></script> just before </body>. 4) Open the page: the background turns yellow. 5) Rename app.js to app2.js without changing the HTML: the colour stops, and the Console shows a red 404 error. This shows that the path must be correct.
Common mistakes
  • Writing <script> tags inside the .js file. Not allowed.
  • Writing code between <script src="app.js"> and </script>. When src is used, the code in between is ignored.
  • Wrong file name or folder path (a 404 error in the Console).
Exam answerJavaScript can be embedded in HTML in three ways: internal (code within the script tag), external (a separate .js file linked with the src attribute) and inline (inside event attributes such as onclick). External scripts are best because they are reusable, cacheable and keep HTML and JavaScript separate.

3. Loading External Scripts

Loading an external script means linking a .js file, and the attributes defer and async decide when it downloads and runs.

Real-life exampleYou are reading a book (the HTML). A friend promises to bring tea (the script). Normal: you stop reading until the tea arrives. defer: you keep reading, and drink the tea when you finish the chapter. async: you keep reading, but the moment the tea arrives you stop and drink it.
DefinitionAn external script is loaded with <script src="file.js"></script>. By default it blocks HTML parsing. defer downloads it in the background and runs it after the HTML is fully parsed, in order. async downloads in the background and runs as soon as it is ready, in any order.
Words to know
Parsing
The browser reading your HTML from top to bottom and building the page.
Block
To stop and wait. "Blocks parsing" = the browser stops reading HTML.
Download
Fetching the file from the server to your computer.
DOMContentLoaded
An event that fires when the HTML is completely read.

3.1 How the browser reads a page

The browser reads HTML from top to bottom, line by line, and builds the page as it goes. This is called parsing.

<h1>Hello</h1>                    ← read, shown
<p>Welcome</p>                    ← read, shown
<script src="app.js"></script>    ← browser must now download + run this file
<p>Bye</p>                        ← waits? That depends on the attribute

3.2 Normal script (no attribute): the browser stops

By default, the browser stops reading the HTML, downloads the script, runs it, and only then continues. The page is frozen during this time.

Two problems:

  1. Slow page: if the script is big or the internet is slow, the user sees a blank page.
  2. Errors: if the script is in <head>, the elements below it do not exist yet, so the script cannot find them.
Example of the error 
<head>
  <script src="app.js"></script>      <!-- runs BEFORE the body is read -->
</head>
<body>
  <h1>Hello</h1>
</body>
// app.js
document.querySelector('h1').textContent = 'Hi';
// ERROR: Cannot set properties of null

The browser has not reached the <h1> yet, so querySelector returns null.

3.3 What is defer?

defer tells the browser: "Download this script in the background, but do not run it until the whole HTML is finished."

Real-life example: You are reading a book (the HTML). A friend says "I will bring your tea (the script)". With a normal script, you stop reading until the tea arrives. With defer, you keep reading while the tea is prepared in the background, and you drink it after you finish the chapter.
Rule of deferMeaning
Does not block HTMLThe page appears fast
Runs after HTML is fully parsedAll elements exist, so no null errors
Runs before DOMContentLoadedA safe place to start your app
Keeps orderWith 2 deferred scripts, the first always runs first
Works only with srcAn inline <script defer> without a file does nothing
Example: order is kept 
<head>
  <script src="library.js" defer></script>
  <script src="app.js" defer></script>    <!-- always runs AFTER library.js -->
</head>

Even if app.js downloads faster, the browser waits and runs library.js first. This matters when your code needs a library.

3.4 What is async? (do not confuse it with defer)

async also downloads in the background, but it runs as soon as the download finishes, even if the HTML is not complete. It pauses the HTML for a moment while it runs. The order is not guaranteed: whichever file downloads first runs first.

Good use of async 
<script src="https://analytics.example.com/track.js" async></script>

Analytics or ads do not depend on your page, so they can run whenever they are ready.

3.5 Comparison

3.6 Common doubts

  • Can I put the script at the bottom of <body> instead? Yes, that also works because the HTML above it is already read. But defer in <head> is better: the browser starts downloading earlier, while it reads the HTML.
  • Does defer work on inline code? No. Only on <script src="...">.
  • What about type="module"? Module scripts are deferred automatically, so you do not need to write defer.
  • Why did getElementById return null? This is the most common beginner error. The script ran before the element existed. Add defer.
Exam answer Scripts are loaded with <script src="file.js">. A normal script blocks HTML parsing while it downloads and runs. defer downloads the script in parallel and runs it after the HTML is fully parsed, keeping the order of scripts. async downloads in parallel and runs as soon as it is ready, with no guaranteed order. Use defer for application code and async for independent scripts such as analytics.

4. Best Practices for Web Page Scripting

Best practices are habits that make your JavaScript safe, fast and easy to understand.

Real-life exampleTraffic rules. You can drive without them, but accidents become likely. Best practices are the traffic rules of coding.
DefinitionBest practices are recommended ways of writing and organising scripts so that pages load fast, code is easy to maintain, and users stay secure.

Practice 1: Keep JavaScript in a separate file

Why? Reusable, cached, and the HTML stays clean. Bad: 200 lines of code inside the HTML. Good: <script src="app.js" defer></script>

Practice 2: Load scripts with defer

The page appears faster and elements exist when your code runs (see topic 3).

Practice 3: Use const and let, not var

var price = 100;     // old, confusing, avoid
const tax = 18;      // will never change
let total = 0;       // will change later
total = price + tax;

var leaks outside blocks and can be re-declared by mistake. const/let stay inside the { } where you make them.

Practice 4: Use addEventListener instead of inline onclick

// Bad
<button onclick="save()">Save</button>
// Good
document.getElementById('save').addEventListener('click', save);

You can attach many listeners to one element and keep HTML clean.

Practice 5: Use textContent, not innerHTML, for user text (security)

Real-life exampleIf a stranger writes a note and you read it aloud, fine. If you treat his note as an order and do whatever it says, he controls you. innerHTML "obeys" the note; textContent only "reads" it.
const input = '<img src=x onerror="alert(\'Hacked\')">';   // attacker's text
box.innerHTML   = input;    // BAD: the hidden script RUNS (this attack is called XSS)
box.textContent = input;    // GOOD: shown as harmless plain text

Practice 6: Never trust user input; validate it

const age = Number(document.getElementById('age').value);
if (Number.isNaN(age) || age < 0 || age > 120) {
  alert('Please enter a valid age');
  return;
}

Practice 7: Handle errors with try...catch

try {
  const data = JSON.parse(text);     // may fail if text is not valid
  console.log(data);
} catch (error) {
  console.log('Something went wrong:', error.message);   // app keeps working
}

Practice 8: Avoid global variables

Variables written outside any function can clash with other scripts. Keep them inside functions or modules.

Practice 9: Use clear names and comments

let x = 5 * 18 / 100;                 // bad: what is x?
const gstAmount = price * 18 / 100;   // good: the name explains itself
Words to know
XSS
Cross-Site Scripting. An attack where a hacker sneaks his own script into your page.
Validate
Check that data is correct before using it.
Global variable
A variable that every part of the program can see and change.
Try it yourself: see XSS yourself (safe test on your own file)Create a page with <div id="box"></div> and run in the Console: document.getElementById('box').innerHTML = '<img src=x onerror="alert(1)">'. An alert pops up: injected code ran. Now run the same with .textContent: the text appears as text and nothing runs.
Exam answerBest practices for scripting: keep scripts in external files, load them with defer, use const/let instead of var, use addEventListener instead of inline handlers, use textContent instead of innerHTML for user data to prevent XSS, validate all input, handle errors with try...catch, avoid global variables, and use meaningful names.

5. Handling Events

An event is something that happens on the page (a click, a key press); handling events means telling JavaScript what to do when it happens.

Real-life exampleA doorbell. The event is "someone pressed the bell". The listener is you, waiting at home. The handler is what you do: open the door.
DefinitionAn event is an action or occurrence detected by the browser, such as a click, key press, form submission or page load. Event handling means attaching a function (the handler) to an element so that it runs when that event happens.

5.2 Event listeners and handlers

Words to know
Event listener
The connection between an element, an event name and a function. It "listens" for the event.
Event handler
The function that runs when the event happens.
addEventListener
The method that creates the connection. Syntax: element.addEventListener('eventName', handlerFunction)

Removes the connection.
Example: a click counter 
<button id="btn">Clicked 0 times</button>

<script>
  let count = 0;                                   // 1
  const btn = document.getElementById('btn');      // 2

  function handleClick() {                         // 3: the HANDLER
    count = count + 1;
    btn.textContent = 'Clicked ' + count + ' times';
  }

  btn.addEventListener('click', handleClick);      // 4: the LISTENER
</script>
  1. A variable count remembers how many clicks so far.
  2. We find the button on the page.
  3. handleClick is the function that does the work: add 1 and show it.
  4. We connect: "on click of btn, run handleClick". Note: no brackets after handleClick. We give the function itself; the browser calls it later.
Try it yourselfRun the example. Then add this line inside handleClick: if (count === 5) btn.removeEventListener('click', handleClick);. After 5 clicks the button stops responding. This shows how to remove a listener.
Common mistakebtn.addEventListener('click', handleClick()) with brackets runs the function immediately and gives its result to the listener. Write handleClick without brackets.

5.3 Event objects

DefinitionThe event object is an object that the browser automatically passes to your handler. It contains details about what happened: which element, which key, mouse position, and more.
Real-life exampleWhen the doorbell rings, you also learn who is at the door and when. The event object carries that extra information.

Example: form validation using the event object 
<form id="f">
  <input id="age" type="number" placeholder="Your age">
  <button>Send</button>
</form>
<p id="result"></p>

<script>
  document.getElementById('f').addEventListener('submit', function (event) {
    event.preventDefault();                       // 1
    const age = Number(document.getElementById('age').value);   // 2
    const result = document.getElementById('result');
    if (age >= 18) {
      result.textContent = 'You can register';
    } else {
      result.textContent = 'You must be 18 or older';
    }
  });
</script>

5.4 Event propagation (bubbling and capturing)

DefinitionEvent propagation describes the path an event takes through the DOM tree. It has three phases: capturing (from the top down to the target), target (the clicked element), and bubbling (from the target back up to the top).
Real-life exampleYou drop a stone in a pond (the target). The ripples spread outward. In the same way, when you click a button, the click "ripples" up to its parent div, then the body, then the whole document, so each of them can react.
Example: see bubbling 
<div id="parent" style="padding:30px;background:#eef">
  Parent
  <button id="child">Child button</button>
</div>

<script>
  const parent = document.getElementById('parent');
  const child  = document.getElementById('child');

  parent.addEventListener('click', () => console.log('2. parent heard it'));
  child.addEventListener('click',  () => console.log('1. child heard it'));
</script>

Click the button. Output:

1. child heard it
2. parent heard it

The event started at the child (target) and bubbled up to the parent. By default, listeners work in the bubbling phase.

To listen during capturing, pass true as the third value: parent.addEventListener('click', fn, true). Then the parent hears it before the child.

To stop bubbling: inside the child's handler write event.stopPropagation(). The parent will no longer hear the click.

Try it yourselfRun the example and click (a) the button, (b) the empty area of the div. In case (b) only the parent speaks, because the target is now the div itself. Then add event.stopPropagation() in the child handler and click the button again: only the child speaks.

5.5 Event delegation

DefinitionEvent delegation means adding one listener to a parent element instead of many listeners to its children. Because events bubble up, the parent can catch events from all children and use event.target to find which child was clicked.
Real-life exampleA school has one principal's office for all classes. Instead of giving every student a personal phone line to the office, there is one reception desk. Any student's request reaches the reception, and the receptionist checks who it came from.
Example: a to-do list where new tasks also work 
<style> .done { text-decoration: line-through; color: gray; } </style>
<ul id="todo">
  <li>Buy milk</li>
  <li>Study JavaScript</li>
</ul>
<button id="add">Add task</button>

<script>
  const list = document.getElementById('todo');

  // ONE listener on the parent <ul>
  list.addEventListener('click', (event) => {
    if (event.target.tagName === 'LI') {            // was an <li> clicked?
      event.target.classList.toggle('done');        // strike it out / undo
    }
  });

  // Adding new tasks later
  document.getElementById('add').addEventListener('click', () => {
    const li = document.createElement('li');        // make a new element
    li.textContent = 'New task';
    list.appendChild(li);                           // put it in the list
  });
</script>
  1. The listener sits only on <ul>.
  2. When you click an item, the click bubbles to the ul. event.target tells us the exact li that was clicked.
  3. We check tagName === 'LI' so that clicks on empty space of the list are ignored.
  4. Tasks added later work immediately because the parent listener already exists. With separate listeners, each new task would need its own.
Try it yourselfRun the page. Click tasks to cross them out. Press "Add task" three times and click the new tasks: they work. Then try writing the same thing by attaching a listener to every li in a loop and notice the new tasks do not respond. That is exactly why delegation is useful.
Exam answer (Events)An event is an action detected by the browser, such as a click or key press. A listener, added with addEventListener, waits for an event on an element and calls a handler function. The browser passes an event object containing details such as type, target and key. Events propagate in three phases: capturing, target and bubbling. Event delegation attaches a single listener to a parent and uses event.target to handle events from its children, which saves memory and also works for elements added later.

7. Handling XML (and comparing it with JSON)

XML and JSON are two text formats for storing and sending data; XML uses tags, JSON uses curly braces.

Real-life exampleA student form can be written as a neat table with labelled boxes (XML: every value has a labelled tag) or as a short note "Name: Asha, Marks: 85" (JSON: compact). Both carry the same facts.

7.1 The structure and syntax of XML

DefinitionXML (eXtensible Markup Language) is a text format that stores data in a tree of tags that you name yourself. It describes data, it does not display it (HTML displays, XML describes).
Words to know
Markup language
A language that uses tags to label content.
Extensible
You can invent your own tags (<student>, <marks>).
Root element
The one outer element that contains everything.
Child element
An element inside another one.
Prolog
The first line that tells the XML version: <?xml version="1.0"?>
Example: a school's data in XML 
<?xml version="1.0" encoding="UTF-8"?>      <!-- prolog -->
<school>                                      <!-- root element -->
  <student id="1">                            <!-- child, with an attribute -->
    <name>Asha</name>                         <!-- child of student -->
    <marks>85</marks>
  </student>
  <student id="2">
    <name>Ravi</name>
    <marks>72</marks>
  </student>
</school>

Rules for correct ("well-formed") XML:

  1. Exactly one root element.
  2. Every opening tag must have a closing tag (or be self-closing like <br/>).
  3. Tags are case-sensitive: <Name> and <name> are different.
  4. Tags must be properly nested: <a><b></b></a> is right, <a><b></a></b> is wrong.
  5. Attribute values must be in quotes: id="1".
  6. Special characters must be written as entities: &lt; stands for <, and &amp; stands for &.

const http = require('http');
const items = [];                                   // our "database" (memory only)

const server = http.createServer((req, res) => {
  const url = new URL(req.url, 'http://localhost:3000');

  if (req.method === 'GET' && url.pathname === '/') {
    res.writeHead(200, { 'Content-Type': 'text/html' });
    res.end('<h1>Welcome</h1>');

  } else if (req.method === 'GET' && url.pathname === '/items') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(items));

  } else if (req.method === 'POST' && url.pathname === '/items') {
    let body = '';
    req.on('data', (chunk) => { body += chunk; });   // data arrives in pieces
    req.on('end', () => {                            // all pieces received
      try {
        items.push(JSON.parse(body));
        res.writeHead(201, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ saved: true }));
      } catch (e) {
        res.writeHead(400);
        res.end('Bad JSON');
      }
    });

  } else {
    res.writeHead(404);
    res.end('Page not found');
  }
});

server.listen(3000, () => console.log('http://localhost:3000'));
  1. Each if is a route: it checks the method and the path.
  2. For GET /items we return the list as JSON text.
  3. For POST, the body arrives in small chunks. We collect them in body and process when end fires.
  4. Anything else gets the 404 "not found" reply.

const fs = require('fs/promises');

  const file = path.join(__dirname, 'notes.txt');
  await fs.writeFile(file, 'Line 1\n');                 // create
  await fs.appendFile(file, 'Line 2\n');                // add
  console.log(await fs.readFile(file, 'utf8'));         // read

  await fs.mkdir(path.join(__dirname, 'out'), { recursive: true });   // new folder
  console.log(await fs.readdir(__dirname));             // list files here
  await fs.rename(file, path.join(__dirname, 'out', 'notes.txt'));     // move
  await fs.unlink(path.join(__dirname, 'out', 'notes.txt'));           // delete
}

Exam answerA network protocol is a set of rules for exchanging data between computers. TCP is connection-oriented and reliable, delivering data in order; UDP is connectionless and faster but unreliable. 15. Child Processes

A child process is another program started by your Node program, so heavy work or other tools can run alongside without freezing the main one.

Real-life exampleA shop owner (the main process) is busy serving customers. When a big order comes, he hires a helper (child process) to pack it in the back room. The owner keeps serving, and the helper tells him when the packing is done.
DefinitionA process is a running program. A child process is a new process created by another (the parent). Node provides the child_process module to create and control them.
Words to know
Parent process
The program that starts the child.
stdout / stderr
The normal output and the error output of a program.
Exit code
A number a program gives when it ends. 0 = success, anything else = problem.
PID
Process ID: the number the system gives each running program.
CPU core
One "brain" of the processor. A 4-core CPU can do 4 jobs at the same time.

Why do we need this? Node runs your JavaScript on one thread. A long calculation freezes everything. Also, Node alone can use only one CPU core. Child processes fix both problems.

15.1 Spawning and managing child processes with Node.js

MethodWhat it doesUse it for
exec(command, callback)Runs a command in a shell and gives all output at onceShort commands with small output
execFile(file, args, callback)Runs a program directly (no shell, safer)Running a known program with arguments
spawn(command, args)Starts a command and streams output as it arrivesLong-running jobs, big output

Example: exec and spawn 
const { exec, spawn } = require('child_process');

// exec: simple, waits for the command to finish, gives all output
exec('node -v', (error, stdout, stderr) => {
  if (error) return console.log('Failed:', error.message);
  console.log('Node version is', stdout.trim());
});

// spawn: starts a command and listens to its output as it comes
const ping = spawn('ping', ['-c', '3', 'localhost']);     // Windows: ['-n', '3']
ping.stdout.on('data', (data) => process.stdout.write('OUT: ' + data));
ping.stderr.on('data', (data) => process.stdout.write('ERR: ' + data));
ping.on('error', (e) => console.log('Could not start:', e.message));
ping.on('close', (code) => console.log('Finished with exit code', code));
// ping.kill();   // would stop the child early
  1. exec runs node -v and gives the answer in stdout once.
  2. spawn starts ping. Its lines appear one by one in data events.
  3. The close event gives the exit code: 0 means success.
  4. kill() stops a child process that is still running.
Security warningNever join user input into a command for exec. exec('ls ' + userInput) lets an attacker type ; delete everything and run it. Use spawn or execFile with an arguments array instead.
Try it yourselfRun the example. Then (1) change the command to spawn('nonexistent-command') and watch the error event; (2) run exec('exit 2', (err) => console.log(err.code)) and see 2. Managing a process means listening to data, error, close, and calling kill() when needed.

15.2 Inter-process communication and messaging

DefinitionInter-process communication (IPC) is the way separate processes exchange data. Processes do not share variables, so they send messages. With fork() Node gives parent and child a ready-made channel: send() and the message event.
Example: give heavy work to a child 
// main.js  (parent)
const { fork } = require('child_process');
const worker = fork(__dirname + '/worker.js');            // start the helper

worker.send({ n: 40 });                                   // 1. parent -> child
worker.on('message', (msg) => {                           // 4. child -> parent
  console.log('Result from helper:', msg.result);
  worker.kill();
});
worker.on('exit', (code, signal) => console.log('Helper stopped. code:', code, 'signal:', signal));

const timer = setInterval(() => console.log('main is still free...'), 300);
setTimeout(() => clearInterval(timer), 3000);

// worker.js  (child)
function fib(n) { return n < 2 ? n : fib(n - 1) + fib(n - 2); }   // slow on purpose
process.on('message', (msg) => {                          // 2. message arrives
  process.send({ result: fib(msg.n) });                   // 3. send answer back
});
  1. The parent starts worker.js as a separate process.
  2. It sends the number 40. The child does the slow calculation.
  3. Meanwhile the parent keeps printing "main is still free...".
  4. When the child finishes, it sends the result back as a message.
Try it yourselfRun node main.js: "main is still free..." keeps printing while the helper works, then the result arrives. Next, copy the fib function into main.js and call fib(40) directly: the "still free" lines stop until it finishes. That shows exactly what a child process protects you from.

15.3 Forking and clustering for parallel processing

DefinitionClustering uses Node's cluster module to start several copies (workers) of a server, usually one per CPU core. All workers share the same port, and the primary process spreads incoming connections among them.
Real-life exampleA bank with one counter (one Node process) has a long queue even though 7 other counters are closed. Opening all 8 counters (workers) serves 8 people at once. The manager at the entrance (primary process) sends each customer to a free counter.
Example: clustered web server with auto-restart 
const cluster = require('cluster');
const http = require('http');
const os = require('os');

if (cluster.isPrimary) {                         // this runs in the MANAGER only
  const cores = os.cpus().length;
  console.log('Primary', process.pid, 'starting', cores, 'workers');
  for (let i = 0; i < cores; i++) cluster.fork();   // one worker per core

  cluster.on('exit', (worker) => {               // if a worker dies...
    console.log('Worker', worker.process.pid, 'died. Starting a new one');
    cluster.fork();                              // ...start a replacement
  });
} else {                                         // this runs in each WORKER
  http.createServer((req, res) => {
    if (req.url === '/crash') process.exit(1);   // to test the restart
    res.end('Handled by worker ' + process.pid + '\n');
  }).listen(3000);
}
  1. The same file runs many times. cluster.isPrimary tells which copy is the manager.
  2. The manager creates one worker per CPU core with cluster.fork().
  3. Each worker starts a server on port 3000. Node shares the port between them.
  4. If a worker crashes, the manager starts a new one, so the site stays up.
fork()cluster
Run one extra Node scriptRun many copies of a server
You send messages yourselfShares the server port automatically
Good for heavy calculationsGood for scaling web servers across cores

Important: workers do not share variables. If you need shared data (logins, counters), keep it in a database. In real projects, the tool PM2 does clustering for you: pm2 start app.js -i max.

Try it yourselfRun the cluster code, then run curl localhost:3000 five or six times. The worker number (PID) changes between replies. Open http://localhost:3000/crash, then watch the terminal: a worker dies and a new one starts. The site keeps working.
Common mistakes
  • Thinking two workers share a variable like count. They do not; each has its own copy.
  • Using exec for big output (it has a size limit). Use spawn.
  • Forgetting to kill() children and leaving background processes running.
Exam answerThe child_process module lets Node run other programs and scripts as separate processes. spawn() streams output, exec() returns buffered output, execFile() runs a file directly and fork() starts a new Node.js process with a built-in IPC channel for messages (child.send() and the message event). The cluster module forks one worker per CPU core; all workers share one server port and the primary restarts workers that fail, which allows a Node application to use all cores and handle more load.

16.1 Debugging and profiling JavaScript code

DefinitionDebugging is finding and fixing errors (bugs) in code. Profiling is measuring where a program spends its time and memory so you can make it faster.
Words to know

A mistake that makes the program give wrong results or crash.

A spot where you tell the debugger "pause here".

The list of lines printed with an error, showing the path that led to it.
Memory leak
A program keeps using more and more memory and never frees it.
Flame graph
A picture where a wider bar means more time spent in that function.

Example: find a bug step by step 
function totalPrice(items) {
  let total = 0;
  for (const item of items) {
    total += item.price * item.qty;
  }
  return total;
}

const cart = [{ price: 10, qty: 2 }, { price: 5 }];   // second item has no qty!
console.log(totalPrice(cart));                         // prints NaN (wrong!)
  1. Notice: we expected 20 + 5 = 25 but got NaN ("Not a Number").
  2. Look at the data: add console.table(cart). The table shows qty is missing in row 2.
  3. Pause and inspect: put debugger; inside the loop and run node --inspect-brk file.js. Open chrome://inspect, click inspect, press F10 (step over) and watch Scope: on the second loop item.qty is undefined, and 5 * undefined is NaN.
  4. Fix: total += item.price * (item.qty ?? 1); (use 1 when qty is missing). The answer is now 25.

Profiling: finding what is slow

  • console.time('label') and console.timeEnd('label'): measure one block of code.
  • node --cpu-prof app.js: creates a .cpuprofile file. Open it in Chrome DevTools, Performance tab, to see which functions take the most time.
  • Chrome DevTools, Memory tab: take heap snapshots to find memory leaks.
  • process.memoryUsage(): shows memory use as numbers.
  • Tools: clinic and 0x draw flame graphs.
Example: compare two ways of adding numbers 
const numbers = Array.from({ length: 1000000 }, (_, i) => i);

console.time('for loop');
let sum1 = 0;
for (let i = 0; i < numbers.length; i++) sum1 += numbers[i];
console.timeEnd('for loop');

console.time('reduce');
const sum2 = numbers.reduce((a, b) => a + b, 0);
console.timeEnd('reduce');

console.log('Memory used:', Math.round(process.memoryUsage().heapUsed / 1024 / 1024), 'MB');

It prints how many milliseconds each method took. Profiling means measuring, not guessing.

Try it yourself: catch a memory leakSave and run node --inspect leak.js with this code: const leak = []; setInterval(() => leak.push(new Array(100000).fill('x')), 100);. // terminal: npm install -D gulp gulp-uglify gulp-clean-css
// gulpfile.js
const { src, dest, series, parallel, watch } = require('gulp');
const uglify = require('gulp-uglify');
const cleanCSS = require('gulp-clean-css');

const scripts = () => src('src/*.js').pipe(uglify()).pipe(dest('dist'));
const styles  = () => src('src/*.css').pipe(cleanCSS()).pipe(dest('dist'));

// run:  npx gulp        (build once)
// run:  npx gulp watch  (keep watching)

  3. .pipe(dest('dist')) saves the result in the dist folder.
